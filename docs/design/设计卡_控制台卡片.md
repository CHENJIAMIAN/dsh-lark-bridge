# 设计卡：控制台卡片（dsh-lark-bridge）

> 状态：现行设计 · 2026-11-10 建档 · 运营方提出"用飞书卡片做成 GUI 可操作"

## 1. 要解决的是"发现不了"，不是"不好用"

桥有六十来条斜杠命令，写得都不差。问题是没人会从聊天记录里发现 `/ws use`，也没人
记得住 `/model deepseek-official/deepseek-v4` 这种参数形状。

所以这不是"把命令包装成按钮"，而是：**把「现在是什么」和「改成什么」放在同一个视野
里**。看到"当前 deepseek/v4"旁边就有个下拉，这件事才成立。

## 2. 卡片的真实边界（决定了设计的形状）

| 能做 | 不能做 |
|---|---|
| 下拉、多选、输入、日期、按钮 | 实时刷新、局部更新、前端联动 |
| 分栏、文本、表格、图表 | 嵌套滚动、分页、树形展开 |
| 表单提交回服务端 | `form` 嵌套、`form` 放进分栏 |

于是交互模型被定死成：**显示状态 → 用控件操作 → 提交后整卡重画 → 看到新状态**。
没有"选完立即生效"，也没有"只更新那一行"。

`form` 只能挂根节点这一条尤其关键：**每个控件组必须是独立的 form，各自带提交按钮**。
把模型和工作区塞进同一个 form 里，卡片直接不合法。

## 3. 架构：加操作 = 加一节

```
src/panel.ts
  panelCard(view)            ← 主循环，只认识"一列 section"
  PANEL_SECTIONS = [modelSection, workspaceSection, actionsSection]
  每个 section: (view) => { id, elements }
```

主循环不认识模型、不认识工作区。新增「切换预设」就是加一个 `presetSection` 并在数组
里加一项，卡片结构一行不用改。

动作路由靠 `action.value.kind = 'dsh-lark-bridge/panel'` 加 `section`/`op` 两段，
和桥里既有的 `goal`、`overdue`、`account` 卡片同一个模式。

## 4. 三个取舍

**下拉而不是按钮**。二十个模型铺成一墙按钮，读的人只需要看见当前那一个。

**没有「新建会话」按钮**。桥里新建会话绑定在入站消息上，没有可用的内部入口。做一个
点了没反应的按钮，比不放这个按钮更糟——用户会以为桥坏了。宁可少一个动作。

**切换后无条件重画**。成功的切换和静默失败的切换不能长得一样，唯一能区分它们的办法
就是把桥现在认为的状态画出来。

## 5. 数据来源

| 显示项 | 来源 |
|---|---|
| 当前模型 | `ctx.agentDefaultModel.currentSelection()` |
| 模型列表 | `ctx.llm.listProviders()` + `listModels()`（`src/model-catalog.ts`） |
| 当前工作区 | 配置的 `cwd` |
| 工作区列表 | `ctx.workspaceRegistry.list()` |
| 上下文占用 | `readContextBreakdown()` 的三段之和 |

模型切换走 `saveSelection`，**必须带上原来的 `reasoningEffort`**——`saveSelection`
是整体替换，漏掉这个字段就会在切模型的同时把推理强度清回适配器默认值。

工作区切换走 `writeChatWorkspace`，对本群之后**新建**的会话生效；当前会话不动，和
`/model` 的语义一致。

## 6. 失败路径

| 情形 | 处理 |
|---|---|
| 模型目录为空 | 显示"宿主没有报出可用的模型目录"，不放空下拉 |
| 没有注册过工作区 | 显示"用 /ws 注册一个" |
| 上下文不可读 | 显示"上下文不可读"，不显示 0（0 会被当成"没占用"） |
| 没有设置持久化层 | toast 报错，卡片不重画（无从重画成什么） |
| 某个 provider 列模型失败 | 只跳过它自己，其余照常 |
| 重画失败 | 记运维通知，不让整个回调崩掉 |
